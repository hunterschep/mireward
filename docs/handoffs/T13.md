## Files and public APIs

- `scripts/dialogue/dialogue_service.gd`: `DialogueService(owner: Node)` with `start(npc_id: StringName) -> ActionResult`, `choose(node_id: StringName, choice_id: StringName) -> ActionResult`, `close() -> void`, `view() -> Dictionary`, and `npc_view(npc_id: StringName) -> Dictionary`.
- `scripts/dialogue/dialogue_rules.gd`: `DialogueRules.validate_definitions(db: Node) -> PackedStringArray` and `validate(definition: Dictionary, db: Node)` for content validation.
- `data/dialogue/dialogues.json`: authored English text, node graph, conditions, choices and effects. No foundation reservations remain.
- `scripts/dialogue/npc_actor.gd`, `scenes/actors/npc.tscn`: reusable civilian interaction and art. See `T13-npc.md` for lifecycle/placement details.
- `tests/unit/test_dialogue.gd`: focused content, branch, stale-input and real NPC integration tests.

`start` and ordinary `choose` return this payload:

```gdscript
{
  "ui_action": "dialogue",
  "dialogue": {
    "npc_id": "mara_venn", "speaker_name": "Reeve Mara Venn",
    "node_id": "mara_venn/mq01_offer", "text": "...",
    "choices": [{"id": "accept_mq01", "text": "I'll bring it back."}],
    "confirmation": false, "max_visible_choices": 3
  }
}
```

Pass the returned qualified `node_id` unchanged to `choose`. Local node IDs in JSON are scoped to their speaker; qualifying the request prevents a stale shop callback from another speaker from matching an identically named node/choice. UI should display at most three choices before scrolling and retain the full returned list. Leave uses the reserved `@leave` choice. Closing returns `ui_action=close_dialogue` and an empty dialogue view. Successful choices also return an `outcome` dictionary containing the actual domain result, including deliveries/pending rewards when applicable. Rejected stale choices include a refreshed `dialogue` view and a plain-language error.

Shop, rest and boss choices return explicit requests, each with `command_pending=true`:

| ui_action | Additional payload | Integration owner action |
|---|---|---|
| `shop` | `shop_id` | Open the real shop panel and fetch current stock/prices. |
| `rest` | `rest_id=inn_bed`, current `cost` | Ask RecoveryService to perform rest; report its actual result. |
| `challenge_rusk` | `entity_id=captain_hall_captain_rusk_01` | Start the real boss encounter through its world adapter. |

These are requests, not claims of a purchase, rest, or started encounter. The Rusk request follows a successfully committed/replayed challenge conversation and closes dialogue. A living Rusk can be explicitly challenged again after recovery; a defeated Rusk refuses new and stale challenges. Root world/UI owns mode transitions and command execution.

## Authoring and validation

Nodes declare local ID, text, conditions, priority, greeting/confirmation flags and choices. Choices declare ID, text, conditions, destination and a single effect dictionary. Destinations are an existing local node, `@root`, or `@close`. Global topics appear on ordinary nodes; confirmation nodes retain only their confirm/cancel/Leave controls.

Condition whitelist: `quest_state`, `objective_pending`, `choice`, `flag`, `alive`. Effect whitelist: `activate`, `complete`, `conversation`, confirmed `choose`, and routed `command`. All quest/objective/choice/speaker references are checked against the existing registries. Wrong givers, wrong final recipients, unsupported operations, missing destinations, malformed nested fields, duplicate IDs, inaccessible graph nodes, long lines, and unconfirmed material-choice effects are rejected. Final ending selection remains at the physical writ table; NPC dialogue cannot commit it.

`npc_view` returns `{npc_id, speaker_name, marker}`, with marker `turn_in`, `quest`, or `none`. The actor uses this view and returns the exact result of `dialogue.start`; it owns no money, quest or mode changes. Rusk's canonical phase line is `ContentDB.dialogues[&"captain_rusk"].data.combat_lines.half_health`.
