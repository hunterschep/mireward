## Behavior delivered

EconomyService implements finite Oswin equipment stock, unlimited Tamsin consumable stock, capacity/funds/ownership validation, exact ending buy multipliers, fixed 35-percent resale prices, and atomic buy/sell. Sold equipment never returns to stock. Failed requests create no receipt or mutation; a repeated committed identity returns its original receipt.

RecoveryService implements bandage/bread/tonic timing, resource caps, one active consumable, damage/death cancellation without item loss, quick-heal input, paused timers, and completion through InventoryService.stage_remove in the shared transaction. It uses the existing PlayerVitals regeneration loop and holds the action lock while healing. Root GameSession ticks recovery at physics priority 20, after combat damage at -20; a real completion-tick damage test passes.

Rest checks the live danger provider, canonical anchor, current scene/proximity, action/travel state, and crowns. Outdoor rest is free; inn rest costs four unless free_inn is true. The transaction commits health/stamina, anchor/location and fee together. Death confirmation similarly charges min(12, floor(crowns*0.10)) once and preserves all permanent inventory, evidence, quest, choice, world, pending-delivery and stock fields. Encounter reset and actual placement use explicit bound callbacks, not invented successful travel.

## Recovery callback contract

- `danger_provider() -> bool`: use EncounterCoordinator.is_dangerous, not cached GameSession.danger. Rest rechecks it inside the committing transaction.
- `reset_encounters() -> ActionResult`: reset living encounters, skip defeated actors, and leave saved loot/world records unchanged. A failed postcommit reset can retry without another fee.
- `travel_handler(anchor_id, reason, apply: bool) -> ActionResult`: apply=false is a pure route/availability/safety preflight. Failure prevents any charge. Apply=true performs real placement after domain commit and must allow the recovery-owned action lock.
- Synchronous travel success means actual arrival. Asynchronous acceptance returns `{pending:true, operation_id:"unique attempt ID"}` and sets GameSession.travelling. It must later clear travelling and call finish_pending_travel with that same ID and an explicit terminal success/failure. Flag clearing alone never means success. Stale completion IDs are rejected.
- Pending/failure results expose committed=true, pending=true, complete=false and the receipt ID. Retry never repeats currency/resource mutation or an already successful reset. Only confirmed arrival releases the recovery action lock and emits recovery_completed/autosave_requested.
- `has_pending_recovery()` is the input-policy hook: the root movement/mode owner must prevent ordinary gameplay while it is true, including after a failed arrival and closing a modal. The recovery service does not create a competing cursor/mode owner.
