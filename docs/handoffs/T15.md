## World and dialogue action protocol

World adapters emit successful ActionResult payloads through root.action_result after physical interaction validation:

| ui_action | Payload | UI behavior |
|---|---|---|
| `loot` | `entity_id`, optional `label` | Re-read WorldStateService; selected quantities and crowns use take_loot/take_crowns. |
| `readable` | `document_id` | Show the canonical retained document view. World first calls QuestService.read_document. |
| `writ` | optional `document_id=village_writ_table` | Revalidate writ review, show three consequences, require explicit permanent confirmation. |
| `training` | optional `step=intro` | Explain actual attack/block/parry bindings and that the straw dummy does not attack or pay rewards. |
| `dialogue` | existing T13 dialogue payload | Fetch the current qualified node and present its choices. |
| `shop` | `shop_id` | Fetch real merchant stock and current buy/sell prices. |
| `rest` | `rest_id` | Call RecoveryService.rest with a unique noncolliding receipt ID. |
| `challenge_rusk` | `entity_id` | Resolve current world entity and call `challenge() -> ActionResult`; unavailable adapters report honestly. |

The loot panel keeps a weak reference to the opened world, rechecks current-world identity and registered source existence before collection, and clears its source whenever inventory closes or the world changes. Reopening the keyboard inventory never collects an old remote container.

The HUD resolves navigation targets from active world entities, then canonical exterior portal/NPC/objective reservations and authored hostile spawns. If no coordinate is available, the actionable location text remains visible. The map names only discovered landmarks. Indoor quests use their exterior portal when appropriate. There is no map travel action. A future Rusk actor must expose `is_duel_active() -> bool` alongside its CombatComponent to show the boss health bar only during the actual duel.

## Navigation and persistence behavior

Title: Continue, New Game, Load Game, Settings, Credits, Quit. Continue is disabled when no valid primary save exists and displays the reason. It selects SaveService's newest valid slot and reports skipped unavailable slots. Load shows all four slots with saved chapter/location/time. Corrupt primaries offer an explicit valid-backup confirmation and are preserved. Pause exposes Resume, manual Save, Load, Settings, current-hint dismissal, failed-autosave retry and confirmed return to title. Overwriting a manual slot asks first; New Game delegates autosave replacement confirmation to SaveService.

Inventory and shop rows show actual descriptions, quantities, currency, capacity, ownership and equipment comparison. Equipped/final weapon sale refusal remains visible. Successful Use closes the modal so real healing time can advance. Damage cancellation and completion report their actual results. Death/recovery screens distinguish an unconfirmed death fee from an already committed recovery awaiting retry.

Settings exposes sensitivity, invert-Y, vertical FOV60-95, bob0-0.08, camera shake, text100/125/150%, Retro/Native, shadows low/high/off, fullscreen, vsync, and five audio levels. Apply settings persists validated values. Binding capture uses actual key or mouse events; Escape cancels capture and remains mandatory Back. Conflicts offer Swap or Cancel and persist both bindings only on confirmation.

Ending confirmation describes the chosen public tally/levy/withdrawal, checkpoint behavior and exact shop-price consequence. After commit, the UI waits for SaveService's real ending_ready result. Pending or failed saving uses GameModeController.set_back_locked(true), not just a hidden Back button. A failure offers Retry save and explicit Continue without saving. Epilogue begins only after successful save or that explicit bypass. Journal replay is a separate pure view using current side-quest flags. UI never reruns ending consequences on replay/load.

Hints use current InputBindings labels and persist dismissal in settings. Movement/look plus journal/map are introduced together, interaction appears at a real offer, combat appears when a hostile is targeted, and healing appears after health loss. Pause can dismiss the current hint. The actual nonrewarding training target and placement are root-owned.
