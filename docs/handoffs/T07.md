## Behavior delivered

`EnemyActor` is a reusable CharacterBody3D for cutpurse, levy spearman, deserter raider, and hollow keeper. It loads canonical EnemyDef stats, articulated VisualFactory art, CombatComponent, CombatHurtbox, capsule collision, and NavigationAgent3D. Stable entity/archetype pairs must exist in the world spawn manifest. Duplicate active IDs are rejected. The captain is deliberately reserved for T20.

States are IDLE, optional authored PATROL, ALERT, CHASE, WINDUP, ACTIVE, RECOVER, STAGGER, RETURN, and terminal DEAD. Attack timing, sweeps, damage, stagger, and guard stamina remain owned by CombatComponent. Spearmen use thrust poses; other archetypes use their authored weapons and shared windup/swing poses. Raiders request a 0.8-second guard after each fourth combat second when their committed attack permits it. Their guard resource remains CombatComponent's 40 maximum and 10/s recovery.

Perception uses the specified 14-meter range and 120-degree frontal cone, with full-circle detection inside 3 meters. World geometry blocks sight and proximity detection. Combat noise alerts unobstructed hostiles within 8 meters. Received damage alerts its recipient outside the normal sight range. A lost target is pursued at its last observed position, not continuously tracked through walls.

After 4 seconds without sight or crossing the 30-meter spawn leash, enemies return. They recover full health only after reaching spawn and remaining out of combat for 5 seconds. A blocked episode requests one extra path assignment after 2 seconds. Recovery to the authored spawn requires at least 6 blocked seconds, no player visibility, and player distance greater than 10 meters. Small legitimate movement starts a new blocked episode. Automatic return and the safe-at-spawn health reset preserve received-hit history.

EncounterCoordinator admits at most two attack reservations, separates windup starts by at least 0.25 seconds, expires abandoned reservations, and releases them on stagger, death, disengagement, and removal. Waiting actors circle or wait. At most twelve nearby living hostiles think; enemies beyond 70 meters sleep with combat processing and avoidance disabled. Ending-neutral/disabled actors cannot attack or receive hostile damage. Neutral camp NPCs should use the separate NPC implementation, not EnemyActor.

## Files and interfaces

- `scripts/ai/enemy_actor.gd`, `scenes/actors/enemy.tscn`: ordinary actor and reusable scene.
- `scripts/ai/encounter_coordinator.gd`: perception-noise routing, reservations, activity budget, and danger queries.
- `tests/integration/test_enemies.gd`: real physics/navigation and shared-combat fixtures.
- `scripts/ai/navigation_arena.gd`, `scenes/actors/navigation_arena.tscn`: delegated reusable arena. See `T07-arena.md` for its independent path probe.

Actor API:

| API | Contract |
|---|---|
| `configure(spawn: Dictionary, player: MirePlayer, coordinator: EncounterCoordinator) -> ActionResult` | Add the actor to the scene tree first. Validates canonical identity, position, optional finite yaw and optional `patrol_points` arrays. Registers itself with the coordinator. |
| `apply_persistent_state(record: Dictionary) -> ActionResult` | Reads `defeated`, `disabled`, and `faction` (`hostile`/`neutral`). Omitted faction/disabled fields retain their current values. Unchanged live records preserve committed attacks. Actual hostility/disabled changes interrupt safely. Dead actors remain dead. |
| `reset_living_encounter() -> ActionResult` | Explicit rest/recovery lifecycle reset to authored spawn, full health, and initial combat state. Refuses dead actors. The caller owns the safe rest/fade boundary. |
| `died(entity_id: StringName)` | Emitted once for an actual combat death. Applying saved defeat does not emit another death. Connect this to the world service's idempotent defeat operation. |
| `authored_loot() -> Dictionary` | Returns `{crowns: int, items: []}` from the definition. It never grants loot or changes persistent state. |
| `is_alive_hostile()`, `is_engaged()`, `can_see_player()`, `has_player_line_of_sight()`, `visible_to_player()` | Current state/perception queries. |
| `navigation_ready()` | Checks the current map iteration and an initialized navigation region at the authored spawn before any path assignment/following. |
| `detach_player()` | Stops simulation and clears the player/navigation target for lifecycle teardown. |

Coordinator API:

- `configure(player)` binds the player and routes its combat ACTIVE phase into noise.
- `register_enemy(actor) -> ActionResult` / `unregister_enemy(entity_id)` manage stable-ID ownership; registration is normally automatic through actor configuration.
- `reserve_attack(actor) -> bool` / `release_attack(entity_id)` manage the two leases; actors use them before requesting a shared combat attack.
- `emit_noise(origin, source_id = player)` applies the 8-meter occlusion rule.
- `is_dangerous() -> bool` recomputes engagement plus the 15-meter hostile line-of-sight rest rule. Use this query at a consequential rest/save decision, not a stale UI value.
- `danger_changed(bool)` supports GameSession's displayed/runtime danger flag. Root owns the production connection.
- `actors()`, `refresh_budget()`, `active_count`, `reservation_count`, and `windup_started(entity_id, combat_time)` support integration and inspection.

The root-approved shared API addition is `CombatComponent.reset_combat(clear_hit_history: bool = true)`. Automatic return and changed live aftermath use `false`; explicit rest/reconstruction retain the default. No damage formula or attack phase duration was duplicated in AI.

## Navigation and integration

The arena has a 40×40-meter floor and a physical wall spanning X ±2, Z ±1. Its authored polygon hole spans X ±2.5, Z ±1.5, providing 0.5-meter clearance. Geometry-only setup is `NavigationArena.new()`, `populate = false`, add to tree, then await `navigation_ready`. The signal waits for the region to enter the map, not merely for a nonzero map iteration.

Path following uses NavigationAgent3D and collision-safe CharacterBody movement, following the pinned [Godot 4.5 navigation guidance](https://docs.godotengine.org/en/4.5/tutorials/navigation/navigation_using_navigationagents.html). Target assignments are at most 5 Hz and occur only after meaningful destination changes or the single stuck retry. Region readiness is cached until the map iteration changes. Avoidance is bounded to six nearby neighbors.

Production order: instantiate actor, configure with its canonical spawn row, connect `died` to `WorldStateService.mark_defeated`, apply `WorldStateService.get_entity_state`, synchronize navigation, then allow normal scene input. Connect coordinator danger to GameSession while retaining commit-time `is_dangerous()` checks. T08/T11 must attach the actual corpse InteractionComponent and read/claim persistent remaining loot. An actor never awards currency directly.

Measured/default implementation choices not otherwise fixed by D04: a 0.25-second alert pause; 0.35-meter path-point tolerance; 0.4-meter navigation target tolerance and avoidance radius; a 3-meter avoidance neighborhood. These remain tuning values for native playtesting.
