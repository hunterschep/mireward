## Behavior delivered

Four stable slots are `autosave`, `manual_1`, `manual_2`, and `manual_3`. They live at `user://saves/<slot>.json`, with `<slot>.json.bak` backups. Settings live separately at `user://settings.json`, also with a backup. When `MIREWARD_TEST_SAVE_DIR` is set, saves use `<test-directory>/saves/` and settings use `<test-directory>/settings.json`; every permanent test runs through the isolated test runner.

Each save contains `schema_version=1`, game version from `application/config/version`, `content_version=1.0.0`, a Unix timestamp, slot metadata, a SHA-256 checksum, and the complete session payload. Slot metadata includes ID, chapter, scene, human-readable location and ending. Canonical payload JSON sorts keys and normalizes JSON numeric representation before hashing. The checksum detects damaged data; it is not an authentication mechanism.

Detached validation runs both SessionValidation and QuestPredicates before loading or writing. It additionally requires every canonical session/player/equipment/flag/shop field, typed authored loot records, known persistent entity IDs and story-consistent undercroft access. Unknown schema/version, malformed metadata, bad checksums, invalid ownership/counts/IDs, inconsistent objective/choice/receipt state, missing story prerequisites and transient actor fields are rejected. Save snapshots use the router's actual loaded scene and that scene's canonical safe anchor. Partial enemy HP, dialogue state, live nodes and input/combat timers are not saved.

The file writer creates a same-directory temporary file, writes, flushes, closes, reads back and validates it. A readable valid primary is copied to a separately validated backup temporary file and renamed over the backup. Only then is the new temporary file renamed over the primary. No valid primary is deleted before replacement. An unreadable existing primary refuses replacement; a corrupt primary never replaces a valid backup. Failed first writes report unsaved progress truthfully. Failed operations clean temporary files and preserve live state.

Slot inspection is read-only. A damaged or missing primary with a valid backup returns `backup_available` with identified backup metadata, without silently selecting it. Loading that backup requires `use_backup=true`. Continue ranks valid primaries by saved timestamp and reports skipped invalid slots; backups remain an explicit Load Game choice.

## Public contracts

SaveService remains the existing autoload. Added pure helpers are `core/save_codec.gd` and `core/settings_validation.gd`; there is no new autoload.

```gdscript

save_settings(candidate: Dictionary) -> ActionResult

rebind(action: StringName, binding: Dictionary, swap: bool = false) -> ActionResult
```

Signals: `autosave_finished(reason,result)`, `load_finished(result)`, and `settings_changed(detached_settings)`. EventBus.save_completed emits only after successful replacement. Public `settings_status` records startup settings-load status. `slot_path` and `settings_path` expose the resolved paths for diagnostics/tests.

Bind after router.configure and RecoveryService.bind_runtime. The save binding connects QuestService, RecoveryService and WorldRouter autosave requests once, plus the committed ending event. Save safety uses a fresh router danger check and refuses death, committed combat/guard, healing/recovery, action lock, travel, loading/writing or active transaction. Load safety is rechecked before preparation and before committing the prepared world. Failed preparation/arrival retain the old snapshot, world and modal stack. A successful load waits for the matching terminal travel_completed operation; accepting a pending journey is never reported as a successful load.

Autosave requests coalesce, then capture the latest committed state at a safe physics boundary. One failure latches automatic retries until an explicit retry or a new meaningful request, preventing repeated I/O every frame. Autosaves never write manual slots. Ending autosaves set `ending_ready` only after successful persistence. A real failed ending save sets `ending_save_failed`; Retry writes the committed state again without repeating its quest transaction. Explicit Continue without saving can release only that same failed committed ending. It preserves unrelated pending reasons and does not immediately retry them. A later rest/quest/transition request resumes ordinary autosaving.

New Game uses root's pure `GameSession.fresh_snapshot()` and prepared world restore; existing autosave/backup replacement requires explicit confirmation. Failed preparation leaves the current session intact. Successful arrival resets all session data and queues the new autosave. Settings and manual saves remain intact. `leave_session` refuses an in-flight load/write/travel/transaction, then disconnects persistence/recovery, clears queued writes, resets the session and marks it inactive. Root must dispose the actual world/ambience and disable or remove its single player after this gate succeeds. Rebind on the next session. Do not synchronously free a router from inside its terminal signal; defer scene teardown or wait a frame.

Settings retain the existing keys. Validation supports FOV 60–95, text scale 1/1.25/1.5, bounded sensitivity/view bob/volumes, rendering/shadow enums, booleans, unique dismissed hint IDs and known digital actions. Bindings are `{type:"key"|"mouse",code:<integer>}` overrides. Conflicts return the other action for Swap/Cancel. A confirmed swap writes both assignments atomically and updates InputMap only after a successful settings write. Pause itself is remappable; Escape cannot be assigned to gameplay and remains independently handled as mandatory Back by GameModeController. Root applies camera/render/window/audio settings from settings_changed.
