## Behavior delivered

The eye-center interaction ray selects the closest visible target whose authored focus point is within 2.5 meters. It checks both the forward world ray and line of sight to that focus point, so an oversized area extending through a wall cannot bypass occlusion. Held E activates once. A later press, changed action, moved target, changed availability, or opened modal is checked again before committing. Unavailable targets retain their reason in the offer. These checks cover R09 and the interaction portion of R08.

GameModeController owns tree pause, mouse capture/visibility, player input release, focus loss, and the modal stack. Competing main panels replace one another. Confirmation/readable panels can stack; settings/save/load opened from pause/title retain that parent. Popping restores the previous panel and keyboard focus. Leaving the controller releases tree pause so scene removal cannot leave the next menu frozen. These checks cover the foundation of R45.

The reusable Area3D adapter supports readable, container, door, NPC, rest, puzzle, and ending interactions. Its handlers perform the actual domain action. An unbound adapter returns `unsupported`; this task does not invent inventory, quest, dialogue, door, or readable success behavior.

## Files and public interfaces

- `scripts/world/interaction_component.gd`: `InteractionComponent extends Area3D`. Exported `entity_id`, `action_id`, `kind`, `prompt`, `enabled`, `focus_offset`, `physical_body`. Implements `get_offer(actor_id: StringName) -> MireTypes.InteractionOffer`, `interact(actor_id: StringName, action_id: StringName) -> MireTypes.ActionResult`, and `focus_position() -> Vector3`.
- `scripts/player/interaction_ray.gd`: `InteractionRay extends Node`. Call `configure(player: MirePlayer, controller: GameModeController)`. Read `focused` and `offer`; call `refresh_focus()` or `interact_focused()`. Signals: `focus_changed(offer: MireTypes.InteractionOffer)` and `interaction_completed(result: MireTypes.ActionResult)`. A null offer clears the HUD prompt. `actor_id` defaults to `player`.
- `scripts/runtime/game_mode_controller.gd`: `GameModeController extends Node`. Call `configure(player: MirePlayer, modal_host: Control = null)`. Public `push_mode(mode: StringName) -> MireTypes.ActionResult`, `pop_mode() -> void`, readable `mode` and `stack`, local `mode_changed(mode)` signal. It also publishes `EventBus.mode_changed` after applying pause and input policy.
- `scripts/ui/modal_host.gd`: `ModalHost extends Control`. Constructs the modal shell at runtime. `register_panel(mode, panel, initial_focus = null) -> ActionResult` transfers the panel into the host; `unregister_panel(mode)` removes and frees it. `show_mode(mode, stack)` is called by the controller. Signal `back_requested` is connected by `configure`. Registered panels replace the empty shell content; only the current panel is visible.
- `tests/integration/test_interaction_modes.gd`: executable physics/input fixtures. No separate fixture scene is needed.

Handler contracts:

```gdscript
component.offer_handler = func(actor_id: StringName) -> MireTypes.InteractionOffer:
    # Pure current-condition query. The offer must identify this component.
    return current_offer
component.action_handler = func(actor_id: StringName, action_id: StringName) -> MireTypes.ActionResult:
    return domain_service_action(actor_id, action_id)
```

The optional offer handler is queried again at commit. The action handler must independently use its domain service's normal validation/transaction API. The adapter never writes GameSession. Its collision shape is authored by the owning world scene. Layer/mask become interactables/zero in `_ready`. Place `focus_offset` on the visible interaction surface, usually around chest/torso height. `physical_body` excludes only the target's own solid body from visibility checks; a direct CollisionObject3D parent is detected automatically. Other walls and doors remain occluders.

## Integration steps

1. Add one GameModeController under GameRoot and one ModalHost under the native-resolution UI/CanvasLayer. After the player and host are ready, call `controller.configure(player, host)`.
2. Add InteractionRay under Player and call `ray.configure(player, controller)`. Player scene and GameRoot wiring are owned by the integration lead and were not edited here.
3. Route HUD focus and action-result feedback from the ray signals. Display the current remapped interaction key alongside the semantic prompt and unavailable reason. This task does not hardcode an E label into UI text.
4. Route all UI/domain mode transitions through the controller. Remove independent cursor/tree-pause assignments from ordinary runtime scenes. The isolated T04 movement arena is not the final owner of those policies.
5. Combat/healing/puzzle timers must use pausable nodes and preserve committed state. Mode changes call `player.clear_input_edges()` and `set_input_enabled`; they must not cancel an attack, refund costs, or reset cooldowns. Current PlayerInput suppresses attack, heavy attack, block, interact, heal, and jump until the held actions are released.

Stack rules: gameplay/title form a single base entry. Main panels replace entries above that base. Repeating the current mode is a no-op. `confirmation` and `readable` push a subordinate entry. `settings`, `save`, and `load` push when opened directly from pause/title. Tab/J/M toggle or replace gameplay menus; Escape closes the top panel or opens pause from gameplay. Unknown mode IDs are rejected without changing state. Death/travel cannot be escaped via `pop_mode`; their completed domain operation must explicitly choose the next mode. Window focus return keeps the pause panel open until the player resumes.
